# Decisions Log

## 2026-05-25: Проект начинается с документации

Решение: сначала создается база знаний в `obsidian`, без генерации приложения и установки зависимостей.

Причина: нужно зафиксировать рамки MVP, чтобы будущая разработка не расползалась.

## 2026-05-25: MVP ограничен одной игрой

Решение: в первой версии реализуется только Scratch Card.

Причина: одна простая игра быстрее проверит промо-сценарий и не потребует сложной экономики призов.

## 2026-05-25: CRM не входит в MVP

Решение: первая версия работает на моковых данных без реальной CRM.

Причина: CRM увеличивает сложность, требует доступа, безопасности, адаптера и тестирования.

## 2026-05-25: Основной стек

Решение: использовать Next.js + React + TypeScript + Tailwind CSS.

Причина: стек подходит для быстрой разработки Telegram Mini App, дает удобные UI и API routes.

## 2026-05-25: Backend нужен для доверенных операций

Решение: Telegram initData, призы, баллы и пользовательские статусы должны проверяться и храниться на backend.

Причина: фронтенду нельзя доверять в вопросах идентичности пользователя и выдачи призов.

## 2026-05-25: Визуальное направление

Решение: mobile-first, темный premium nightlife стиль с теплыми золотыми акцентами.

Причина: интерфейс должен соответствовать Burlesque и ощущаться как мобильное приложение внутри Telegram.
