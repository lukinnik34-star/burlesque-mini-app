# Telegram Auth

## Принцип

Telegram Mini App передает `initData`. Эти данные можно использовать для идентификации пользователя только после серверной проверки подписи.

## Что важно

- Не доверять данным пользователя с фронта.
- Не считать `telegramId` надежным, если он пришел только из client-side состояния.
- Проверять `initData` на backend.
- Проверять срок жизни `auth_date`.
- Хранить связь пользователя с `telegramId` на сервере.

## MVP

В MVP можно показывать моковые данные профиля, но кодовая архитектура должна учитывать будущую server-side валидацию.

## Будущий поток авторизации

1. Клиент получает `initData` через Telegram Mini App SDK.
2. Клиент отправляет `initData` на backend.
3. Backend проверяет подпись через bot token.
4. Backend создает или обновляет пользователя.
5. Backend возвращает безопасный профиль или сессию приложения.

## Нельзя

- Выдавать призы только на основании client-side user id.
- Доверять баллам, промокодам и статусам с фронта.
- Передавать bot token на фронт.
