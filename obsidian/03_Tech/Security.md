# Security

## Главные правила

- Telegram initData валидировать только на backend.
- Не доверять client-side данным о пользователе.
- Не хранить секреты во фронтенде.
- CRM подключать только через backend.
- Выдачу призов делать серверной операцией.
- Ограничивать повторные игровые попытки на сервере.

## MVP

В MVP используются моковые данные, но не нужно закладывать паттерны, которые потом придется ломать:

- не писать код так, будто фронт является источником истины;
- не смешивать секреты и публичные переменные;
- не привязывать UI напрямую к будущей CRM;
- не создавать небезопасные промокоды на клиенте.

## Будущие меры

- Проверка подписи Telegram initData.
- Проверка `auth_date`.
- Rate limiting для игровых endpoints.
- Серверное хранение истории попыток.
- Серверная выдача призов.
- Логи важных действий.
- Минимизация персональных данных.
- Разделение публичных и приватных переменных окружения.

## Потенциальные риски

- Подмена Telegram-пользователя.
- Повторное получение призов.
- Перебор промокодов.
- Утечка CRM-ключей.
- Слишком доверенный фронтенд.
