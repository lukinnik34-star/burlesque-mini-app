# Architecture

## Общий подход

MVP строится как Next.js приложение в папке `app/`. На первом этапе данные моковые, но структура должна оставлять место для backend-валидации Telegram, базы данных и CRM-интеграции.

## Предполагаемые слои

### UI layer

- Страницы и компоненты React.
- Нижняя навигация.
- Карточки мероприятий, игр, профиля и адресов.

### Data layer

- Моковые данные для MVP.
- Позже - запросы к API routes.
- Затем - серверные запросы к PostgreSQL/Prisma и CRM.

### API layer

- Next.js API routes.
- Проверка Telegram initData.
- Выдача данных профиля.
- Выдача мероприятий.
- Логика призов и игр.

### Integration layer

- CRM adapter.
- Maps/deeplinks.
- Внешние ссылки на сайт, лендинги, звонки и мессенджеры.

## Важный принцип

Фронтенд не должен хранить доверенные решения о пользователе, призах и правах. Все важные решения должны быть перенесены на backend, даже если в MVP временно используются моки.

## Возможная структура будущего app

- `app/` - Next.js app router.
- `components/` - UI-компоненты.
- `features/` - функциональные зоны: events, games, profile, clubs.
- `lib/` - утилиты, Telegram helpers, mock data.
- `app/api/` - API routes.
- `types/` - общие TypeScript-типы.
